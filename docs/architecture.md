# FontFerry 架构与工程约束

基线为 v0.2.0-alpha.6（a7fb8ca）。本文同时记录现有机制与目标约束。本版实施范围和验证状态见 [当前版本交付单](milestone.md)，用户承诺见 [产品章程](product.md)。

## 现有机制

GUI 与 CLI 已共用 Rust 引擎、SQLite 所有权账本与跨进程操作锁。平台适配已用日志和匹配收据约束提交后清理。当前回滚依赖本机加载的来源定义，逐字体暂停与脱离目录的本地恢复属于目标设计。alpha.7 已提供可选 GitHub 代理与分阶段安装反馈。 [引擎](../crates/fontferry-core/src/engine.rs) · [安装适配](../crates/fontferry-platform/src/install.rs) · [SQLite](../crates/fontferry-platform/src/state.rs)

## 1. 进程和职责

沿用 Svelte、Tauri、Rust 与 SQLite。桌面应用和系统定时启动的 CLI 使用同一 Rust 引擎、用户数据目录和跨进程写锁。平台适配沿用 Windows、macOS、Linux 的字体注册和任务机制。

| 模块 | 职责 |
|---|---|
| Svelte | 展示候选、进度、当前状态和恢复操作。交互提交字体 ID、变体、候选标识和用户确认。 |
| Tauri / CLI | 输入校验、流程入口、进度转发、通知和只读诊断。Tauri 负责应用自更新，CLI 负责受系统调度的字体检查。 |
| fontferry-core | 版本排序与渠道、许可、字体包选择、更新策略、状态转换和操作编排。GUI 与 CLI 共享决策路径。 |
| fontferry-platform | 上游访问、暂存与解析、SQLite、系统字体注册和计划任务。沿用现有所有权日志和收据。 |

GUI 和 CLI 各自加载定稿的来源定义。SQLite 持有自定义来源和用户策略，签名目录使用已校验版本。写操作使用跨进程锁，提交已确认候选前读取当前共享状态。进程内目录副本只供展示。

## 2. 状态及持久化

| 对象 | 最小状态 | 约束 |
|---|---|---|
| 来源定义 | 稳定身份、发布源、许可修订、制品规则和变体 | 内置目录不能覆盖自定义定义。冲突来源单独标为待处理，已管理记录保持可见。 |
| 关注与观测 | 用户关联的来源、手工确认版本、可选扫描结果与时间 | 影响版本追踪，独立于所有权。 |
| 管理记录 | 字体 ID、安装版本、变体、受管文件与上一个快照 | SQLite 是所有权权威。增加本地操作所需的最小身份信息，使恢复和移除可独立于远程目录。旧记录使用经验证的历史定义或账本补齐。证据不足时停用相应的恢复，并保留可验证的移除操作。 |
| 更新策略 | 手动确认、自动安装或已暂停，以及暂停原因 | 新用户默认手动。旧版迁移保留计划任务的检查权限。策略写入与字体操作共用锁，后台在执行前重读。 |
| 检查结果 | 本次尝试、上次成功时间、选定版本、候选身份和失败原因 | 来源身份或影响制品的定义、变体变化时使缓存失效。旧缓存可以显示历史。安装需要在线重新确认候选。 |
| 运行与活动 | 任务触发及结束时间、逐字体结果、阶段与类型化错误 | 区分并发跳过、部分失败、中断和成功。通知失败只影响通知。活动写入失败不能颠倒已提交状态。 |

沿用 schema 迁移机制。任何创建或迁移账本的启动路径先取操作锁，再检查待恢复日志与可识别的旧状态证据。升级保留旧版所有权、快照、收据与许可。账本缺失且存在恢复日志或管理快照时进入诊断模式。若用户已删除全部管理状态，系统无法判断外部文件的历史归属，可以初始化空账本，现存字体统一按外部文件处理。坏账本在诊断期间保留原样。

升级首次切换策略前，安装器停止旧 GUI 和后台写入，确认已注册任务指向当前可执行文件。旧程序不认识逐字体暂停策略，程序版本回退需要单独做数据兼容检查。候选发布必须验证从 alpha.6 原地升级后只有新版能执行安装任务。

## 3. 安装、更新与恢复

**候选绑定。** 候选包含字体和来源身份、渠道、版本、变体、许可修订、稳定制品标识及可取得的上游摘要。用户确认后，安装重新读取发布元数据。目标或制品身份改变时返回「候选已变更」。手动操作重新确认，后台操作暂停该次安装并通知。匹配歧义先修正制品规则。短期跳转地址变化使用稳定标识比对。上游未给摘要时仍要求唯一匹配、可信 HTTPS 来源及本地解析与安全检查。界面按实际校验结果标明保证范围。同一制品标识下相同名称的无摘要内容仍可能被上游替换。

**操作顺序。** 保留每用户一个字体写入者。写路径取得进程内协调和操作文件锁，先处理待办恢复，再重读策略、来源与账本。下载和解析仅写暂存目录。写入系统前检查所有权边界、重名、文件与空间。首版允许沿用覆盖网络请求的写锁，使用有界请求和明确的忙碌状态。将准备工作移出写锁需要独立验证陈旧候选和并发提交。

**提交与清理。** 平台写入前保留上一版快照与持久化日志。SQLite 事务同时更新所有权与绑定操作 ID、日志摘要和结果的收据。只有收据、账本与平台文件核验相符，才允许清理。操作投影区分准备中、提交前失败、已提交、已提交待清理、待修复。异常后按日志、收据与受管文件推导状态。缺匹配收据或文件出现外部更改时保留证据。自动恢复仅在满足现有核验条件时继续。

**回滚与自动安装。** 回滚取得同一写锁后，先持久写入「已暂停」再修改字体。暂停写入失败时不开始回滚。后续恢复失败，暂停仍有效。后台即使已经在锁外取得候选，也要在锁内复读策略及当前版本。手动更新保留暂停状态，只有用户主动恢复自动安装才解除。离线回滚依赖已验证的账本、快照与平台适配。

**应用卸载。** 升级保留后台任务和数据。真实卸载验证任务归属，阻止该任务再次启动并确认现有写入者退出后，才移除应用。冲突或无法停止时保留应用与数据并提供重试入口。保留字体、账本、快照与恢复证据。逐字体移除仍走统一所有权检查。

## 4. 网络、目录与发布

默认沿用常规网络设置。用户可显式填写回环地址 HTTP 代理端口。字体客户端限定已知 GitHub HTTPS 主机使用代理，重定向逐跳检查。自定义主机继续校验连接实际使用的 DNS 结果、HTTPS 与非公网地址边界。端口未监听或返回异常时显示错误及操作入口，由用户决定切回默认网络。应用自更新使用 Tauri 支持的代理配置，并保留安装包签名验证。

使用独立的 Ed25519 公钥验证目录原始字节。正文与签名作为一组持久提交，避免中断留下半组缓存。更新校验失败时继续使用最后可验证的一组，无可用远程版本时使用内置目录。目录只影响后续候选与发现流程，已有所有权、恢复和移除基于本地记录继续。上游制品校验、目录签名和应用更新签名分别覆盖各自对象。

应用通道与已发布清单匹配。稳定通道缺清单时显示不可用和手动入口，测试版由用户明确选择。稳定包沿用平台签名与 Tauri updater 验签门槛。Linux 系统包由其包管理器更新。

## 5. 诊断与兼容

启动把本地外壳与账本恢复分开。遇到缺账本、无匹配收据、目录冲突或写锁占用时，界面仍展示可获得的本地内容及操作限制。诊断入口在常规状态初始化失败时仍可运行，报告可安全读取的版本、通道、失败阶段、恢复类别和任务状态。脱敏文本由用户主动复制，剔除用户名、绝对路径、代理凭据、URL 查询参数和私有源详情。

单元测试覆盖策略和状态推导，故障注入覆盖各个系统文件和账本写入边界，CLI 与 GUI 共用用例验证并发。各平台安装器、字体真实可选、任务启停和签名升级由原生测试账户验证。

## 字体包解析

目录模板在维护阶段展开为签名 JSON。客户端沿用稳定规格 ID。GitHub 附件用规格正则精确选择，预览和下载共享匹配规则。多个规格引用同一附件时只下载一次。规格可声明确切的包内文件名，缺失或出现重名时在注册前停止。系统安装能力和界面展示由目录与客户端共同约束。

## 后续变更的回归判据

| 约束 | 触发验收的反例 | 通过判据 |
|---|---|---|
| A05 回滚暂停 | 后台持有陈旧候选，或暂停持久化失败 | 锁内复读发现暂停时跳过更新。暂停写入失败时字体无变化，回滚本身失败时仍保持暂停。 |
| A07 本机管理独立性 | 目录条目下架、正文签名不配对或 ID 冲突 | 已管理字体仍可访问、可验证移除，证据充分时可离线恢复；其余目录条目仍可用。 |
| A08 独立诊断 | 缺账本或恢复错误阻断常规启动 | 诊断和脱敏复制可用。原日志、快照及字体保持完整。 |
| A10 安装生命周期 | 卸载与后台启动竞争，或升级改变安装路径 | 升级保留任务并核对新版路径。真实卸载清理自身任务并保留选定字体、账本及快照。冲突时安全停止操作。 |
| A11 策略迁移 | 旧版只有全局自动安装授权 | 保留每日检查和现有账本；逐字体自动安装需重新授权。 |
| A12 旧写入者 | 旧进程在策略迁移后继续执行 | 升级先停止旧写入者并验证任务入口，不确定时阻断升级。新策略与暂停跨重启保留。 |
