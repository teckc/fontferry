# FontFerry 当前版本交付单

**目标：Windows 用户能从官方入口安装 FontFerry，在常用应用中选到「得意黑」。普通网络无需配置代理，遇到 GitHub 连接失败时能在 FontFerry 内理解原因并重试。**

基线为已发布的 v0.2.0-alpha.6（a7fb8ca）。本次候选为 v0.2.0-alpha.7，处于实现与验收阶段。 [产品章程](product.md) · [架构与工程约束](architecture.md)

## 本次交付

- 首次启动提供直接浏览字体的入口。用「得意黑」验证完整安装，用一款多变体字体验证候选和字体包选择。
- 在字体详情区分检查、下载、验证和系统安装阶段。故障提示说明当前阶段和可用操作，支持就地重试。安装成功后显示实际版本和字体族。
- 默认保留普通网络路径。本机 HTTP 代理为可选项，覆盖已知 GitHub 查询和下载路径。连接测试分别反映查询和制品主机是否可达。若代理设置仍需重启生效，从提示返回同一字体即可重试。
- 应用更新通道缺有效清单时显示原因和官方手动入口。当前版本交付包含从 alpha.6 的原地升级验收。
- 既有字体回滚及账本保护纳入回归。逐字体自动安装和暂停、完整的只读恢复工作区、自定义源生命周期、卸载时的计划任务清理留待独立交付。涉及这些机制的长期约束及反例保存在 [架构文档](architecture.md#后续变更的回归判据)。

## 本版验收

在 Windows 标准用户测试账户用真实候选安装包完成。每项记录应用和平台版本、网络模式、字体与制品版本、用户可见结果及证据链接。复用现有自动化和有效实测，补齐候选的原生验证。

| ID | 场景 | 通过判据 | 状态与证据 |
|---|---|---|---|
| A01 | 新用户在常规网络首次安装 | 下载安装包后可独立从目录选中「得意黑」，无需配置代理，在目标应用中可选。未检查或部分失败时，页面能区分未知状态、历史缓存和真实检查结果。 | 待验证 |
| A02 | 查询成功但制品下载失败，或显式代理停止 | 字体详情显示失败阶段，现有字体不受影响。代理网络中填写本机端口后可按提示重试，成功下载并将字体注册到当前用户。自定义主机仍受公网校验。 | 部分验证。此前用 Rust 网络层经 Windows FlClash 查询并下载得意黑 v2.0.1（5,781,344 字节）。开发分支的端口设置保存后需要重启。Windows 候选 GUI、常规网络和系统注册待验证。 [HTTP 实现](../crates/fontferry-platform/src/http.rs) |
| A03 | 多变体字体的候选在确认后改变 | 正常流程安装确认的变体。制品身份、已有摘要或许可修订变更时要求重新确认。匹配出多个候选时，在系统写入前阻断并解释。仅临时跳转地址变化且稳定身份仍一致时可继续。 | 待验证 |
| A04 | 本机已有会与待装字体冲突的外部字体 | 写入前解释冲突。控制文件、系统注册和 FontFerry 账本均保持原样。 | 待验证 |
| A06 | 在记录操作日志后、注册后或账本提交后中断 | 证据不足时保留文件、账本和恢复记录。已提交且证据匹配时可继续清理，重试不重复写入。既有受管字体可继续使用或明确进入恢复状态，控制字体无变化。 | alpha.6 有收据和保留证据的自动化覆盖。候选故障注入和原生回归待验证。 [安装适配](../crates/fontferry-platform/src/install.rs) · [Windows 检查](windows-upgrade-checklist.md) |
| A09 | 稳定通道无清单、测试通道有候选，或签名失败 | 可区分通道不可用、该平台无候选和已是最新。手动获取入口可用。无有效签名不启动安装。 | alpha.6 基线曾观察到稳定清单返回 404、测试清单可读。候选界面及签名更新待验证。 |
| R01 | 从 alpha.6 原地升级真实 Windows 安装包 | 保留安装位置、用户设置、受管字体、备份和恢复证据。旧版不再运行，能正常启动新版。 | alpha.6 发布冒烟已覆盖从 alpha.5 升级。下一候选的 alpha.6 → 新版待验证。 [冒烟脚本](../scripts/windows-installer-smoke.ps1) |

候选须通过表中全部门禁，且 README 和 Release 说明与安装包实际能力一致。现有发布签名和平台检查沿用 [发布与目录签名](release-signing.md)。

## 实施顺序

1. 先接通首启、安装反馈和重试，补齐直连与显式代理用例。
2. 验证候选绑定、外部字体控制组和中断恢复。已有安全机制作为回归基线。
3. 用真实候选包复测升级和通道，写明支持范围、手动升级入口及已知限制；通过验收后更新用户入口。
